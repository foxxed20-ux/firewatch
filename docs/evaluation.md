# Как проверить FireWatch

[← Главная](../README.md) · [Модельный протокол](../README_MODEL.md) · [История изменений](../CHANGELOG.md)

## Что подтверждает каждый вид проверки

| Проверка | Что доказывает | Чего не доказывает |
| --- | --- | --- |
| Контрактные тесты | Форматы, классы, RLE, поведение ошибок, формулу метрик | Качество обученной модели |
| Validation на train-разбиении | Качество выбранного кандидата в объявленном протоколе | Оценку закрытого конкурсного test |
| Полный запуск `inference.py` | Обработку входов и формирование всех строк CSV | Правильность скрытых ответов |
| `/health/live` | Доступность процесса API | Готовность моделей и корректность карты |
| `/health/ready` и реальный анализ | Готовность зависимостей и конкретный сквозной сценарий | Надёжность на любых данных и нагрузках |
| Браузерная проверка | Работу выбранных пользовательских сценариев | Полное покрытие всех устройств и браузеров |

## Метрики

```text
Score = 0.35 × F1_AF + 0.35 × IoU_burn + 0.30 × mIoU_severity
```

Счётчики TP/FP/FN суммируются по чипам. Маска гари объединяет классы BS 1–3; severity оценивается по отдельным классам. Пустой знаменатель обрабатывается согласно конкурсному контракту. Реализация и контрольные примеры — [metrics.py](../competition/metrics.py) и [test_competition_contract.py](../tests/test_competition_contract.py).

При публикации измерения обязательно указываются:

1. Bundle и ревизия кода.
2. Данные и split; способ выбора порога и постобработки.
3. Все три компонента метрики, а не только итоговый Score.
4. Среда исполнения, время полного прогона и ограничения.
5. Проверки submission: строки, классы, порядок, RLE round-trip.

## Данные и отсутствие утечки

Открытый train включает 420 AF и 224 BS-чипа. В [split.json](../artifacts/split.json) зафиксированы 515 обучающих и 129 валидационных чипов. Геосетки изолированы; у BS дополнительно разделены события. Отсутствующие AF fire_event_id не заменяются выдуманными идентификаторами — ограничение отражено в [аудите](../artifacts/data_inspection.json).

На вход модели не передаются ID события, координаты, даты и статистика целевой маски. Нормализация обучается только на train. Пороги и выбор между CNN/LightGBM определяются на validation, поэтому эта выборка не является независимой финальной оценкой.

Примеры для карты берутся из разрешённых геопривязанных данных. Если используются validation-примеры из открытого train, этот факт показывается пользователю; визуальная удачность выбранного примера не является метрикой.

## Готовность релизного кандидата

### Проверенный комплект v2

| Проверка | Наблюдавшийся результат | Доказательство |
| --- | --- | --- |
| Выбор рецепта | AF CNN + LightGBM; BS LightGBM; validation Score 0,702716 | [Рецепт v2](../artifacts/ensemble-v2/selected_recipes.json) |
| Полный offline CLI | 269 test-чипов, 447 строк данных и заголовок; 540,3 с в среде команды | [Независимая проверка CSV](../artifacts/ensemble-v2/evidence/submission_validation.json) |
| Повтор инференса | Все 129 validation-чипов; изменение каждой компоненты метрики равно 0 | [CPU replay](../artifacts/ensemble-v2/evidence/cpu_validation_replay.json) |
| Перенос модели | Четыре маски совпали побайтово на Windows и Linux CPU | [Проверка публичных масок](../artifacts/service/public-mask-parity.json) |
| Публичный сервис | 79 HTTP-проверок, 6 основных заданий, браузерные AF/BS и экспорт; откат и восстановление | [Сводка приёмки](evidence/service-release-summary.json) |
| Дополнительная геометрия | Положительный Polygon с отверстием; исключённая область не входит в контуры | Та же сводка приёмки |

Это доказательства конкретного комплекта `official-ensemble-v2` и сервисной поставки `20260919-ensemble-3`. Повтор сохранённых весов не является повторным обучением. Замер CLI выполнялся при параллельном обучении и не определяет конкурсные баллы за скорость. Private test Score неизвестен до оценки организаторов.

Сравнение дополнительных BS-кандидатов продолжается. При замене весов повторяются CLI, проверка CSV, сверка масок и сквозная приёмка. CI на GitHub/GitVerse оценивается по фактическому результату запуска, отдельно от локальных проверок.

### Условия следующей поставки

Публикация исходников и выпуск законченной модели — разные этапы. До финального выпуска проверяются:

- поставка согласованных AF/BS-весов, manifest и SHA-256;
- воспроизводимые команды установки и инференса;
- полный CSV, совместимый с официальным шаблоном;
- успешный анализ через API с настоящим bundle;
- отображение результатов, площадей и скачивание артефактов в браузере;
- корректные состояния «нет данных», «модель не готова», ошибочный AOI и период;
- отсутствие данных, секретов и локальных служебных файлов в Git;
- соответствие README фактическому состоянию поставки.

Указанные выше проверки закрыты для v2. Проверки будущего комплекта и независимое качество не наследуют этот статус автоматически. Отсутствующие измерения не заменяются оценками или обещаниями.
